# 运行部署说明

## 一、环境要求

### 后端

- JDK 17
- Maven 3.8 及以上
- MySQL 8.0

### 前端

- Node.js 20.19 及以上，或 22.12 及以上
- npm 10 及以上

## 二、默认端口

| 服务 | 端口 |
|------|------|
| 后端 | `18011` |
| 前端开发服务 | `18012` |

如果本机端口冲突，可以自行修改配置，但前后端地址要一起调整。

## 四、数据库准备

### 1. 创建数据库和表

进入项目根目录后执行：

```bash
mysql -u root -p < emolink-backend/sql/mysql-init.sql
```

如果希望补充文章测试数据，再执行：

```bash
mysql -u root -p emolink < emolink-backend/sql/article-seed.sql
```

### 2. 本地演示数据和账号

初始化文章后，可以载入虚构的演示数据：

```bash
mysql -u root -p emolink < emolink-backend/sql/demo-seed.sql
```

- 演示用户：`emolink_demo / admin123`
- 管理员：`admin / admin123`

以上账号仅用于本地演示。部署前必须更改密码，禁止用于真实用户数据。

## 五、后端配置说明

后端配置文件位置：

`emolink-backend/src/main/resources/application.yml`

运行前在终端设置环境变量：

### 1. 数据库

```bash
export DB_URL='jdbc:mysql://127.0.0.1:3306/emolink?useUnicode=true&characterEncoding=utf-8&useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true'
export DB_USERNAME='root'
export DB_PASSWORD='你的数据库密码'
export JWT_SECRET='替换为至少32位的随机字符串'
```

### 2. DeepSeek

```bash
export DEEPSEEK_API_KEY='你的 DeepSeek Key'
```

Key 只保存在运行环境中，不要提交到 Git 或放入源码压缩包。未配置时，日记 AI 建议和周报 AI 分析不可用。

### 3. 跨域

```yaml
app:
  cors:
    allowed-origin: http://localhost:18012,http://127.0.0.1:18012
```

前端地址变了，这里要跟着改。

### 4. 上传目录

```yaml
app:
  upload:
    dir: uploads
```

这里使用相对路径。也就是说，后端从哪个目录启动，`uploads/` 就会落在哪个目录下面，不依赖某台电脑的固定路径。

## 六、启动方式

### 方式一：开发环境启动

#### 启动后端

```bash
cd emolink-backend
mvn spring-boot:run
```

启动成功后访问：

`http://localhost:18011`

#### 启动前端

```bash
cd emolink-frontend
npm install
npm run dev -- --host 0.0.0.0 --port 18012
```

启动成功后访问：

`http://localhost:18012`

### 方式二：打包后启动

#### 打包后端

```bash
cd emolink-backend
mvn clean package
```

打包完成后运行：

```bash
java -jar target/emolink-backend-0.0.1-SNAPSHOT.jar
```

#### 构建前端

```bash
cd emolink-frontend
npm install
npm run build
```

构建完成后，`dist/` 目录可以交给 Nginx 或任意静态资源服务器托管。

## 七、推荐部署方式

### 1. 单机部署

适合课程项目答辩、内部演示、小规模使用。

- 后端：`java -jar`
- 前端：Nginx 托管 `dist/`
- 数据库：本机 MySQL

### 2. 服务器部署

推荐思路：

- 前端静态资源交给 Nginx
- `/api` 和 `/ws` 反向代理到 Spring Boot
- MySQL 独立部署
- `uploads/` 目录跟后端部署目录放在一起，并做好备份

## 八、Nginx 代理时要注意的点

### 1. API 代理

把 `/api/` 转发到后端 `18011`。

### 2. WebSocket 代理

把 `/ws` 转发到后端 `18011`，并保留升级头：

- `Upgrade`
- `Connection`

否则伙伴信箱无法建立 WebSocket 连接。

## 九、首次验收建议

部署完成后，建议按这个顺序验收：

1. 打开登录页，测试普通用户登录
2. 新增一条情绪日记，确认能收到 AI 建议
3. 打开日报和周报，确认图表正常渲染
4. 发布一条普通树洞内容，确认直接显示
5. 发布一条包含敏感词的树洞内容，确认进入待审核
6. 管理员登录后台，确认可以审核帖子和评论
7. 两个不同账号进入伙伴信箱，确认能匹配并聊天

## 十、常见问题

### 1. 后端启动失败，提示数据库连接错误

先检查：

- MySQL 是否启动
- 数据库名是否为 `emolink`
- 用户名密码是否正确

### 2. 情绪建议接口报错

优先检查：

- `deepseek.api.key` 是否有效
- 服务器能否访问 DeepSeek 接口
- 后端日志里是否有 502 相关错误

### 3. 头像上传后访问不到

先看：

- 后端是否从预期目录启动
- `uploads/` 是否已经生成
- 数据库里的头像地址是否是 `/uploads/...`

### 4. 伙伴信箱连不上

一般从这几处查：

- 后端是否启动
- `/ws` 代理是否正确
- 浏览器控制台是否有 WebSocket 错误
- token 是否过期

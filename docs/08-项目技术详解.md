# 项目技术详解

## 一、项目定位

EmoLink 是一个面向大学生的情绪管理平台。它不是单纯的日记工具，而是把记录、分析、内容阅读、匿名表达和陌生人陪伴放在了一起。

整个项目采用前后端分离：

- 前端负责页面、状态管理、图表和 WebSocket 客户端
- 后端负责业务规则、权限控制、数据库访问、AI 调用和消息分发
- MySQL 负责业务数据落库
- DeepSeek 负责生成情绪建议和周报分析

## 二、主要功能和落地方式

| 功能 | 说明 | 主要技术 |
|------|------|---------|
| 用户体系 | 注册、登录、个人资料、改密、管理员角色识别 | Spring Boot、JWT、BCrypt、Pinia |
| 情绪日记 | 记录情绪、修改、查询、搜索 | Spring Boot、MyBatis-Plus、Vue |
| 情绪报告 | 日报波动图、周报图表、AI 分析 | ECharts、DeepSeek |
| 心理知识库 | 分类列表、搜索、详情、收藏 | MyBatis-Plus、Markdown 渲染 |
| 匿名树洞 | 发帖、评论、点赞、审核 | sensitive-word、管理端审核 |
| 伙伴信箱 | 随机匹配、聊天、结束对话 | WebSocket、STOMP |
| 管理后台 | 用户管理、文章管理、审核台、统计图表 | JWT 权限、Element Plus、ECharts |

## 三、重要技术用了什么，为什么这么用

### 1. Spring Boot 2.7

后端核心框架。控制器、配置类、拦截器、WebSocket 配置都在这个框架里组织。

使用位置：

- `controller/`：接口入口
- `service/`：业务逻辑
- `config/`：跨域、Bean、MyBatis、MVC 配置
- `interceptor/`：统一认证拦截

### 2. MyBatis-Plus

用来做数据库访问和分页查询。这个项目的 CRUD 很多，直接用 MyBatis-Plus 能把大量样板代码压缩掉。

使用位置：

- `mapper/` 目录保存数据访问接口
- 各业务服务里通过 `Wrappers.lambdaQuery()` 组织查询条件

### 3. JWT

用户登录后，后端签发 token。之后所有需要登录的接口都通过拦截器读取 token，再把 `userId` 放到请求上下文。

使用位置：

- `util/JwtUtil.java`
- `interceptor/JwtInterceptor.java`
- `websocket/JwtHandshakeHandler.java`

### 4. WebSocket + STOMP

伙伴信箱是实时聊天，不适合轮询。后端用 STOMP 消息代理做点对点推送，前端用 `@stomp/stompjs` 建立连接。

使用位置：

- 后端：`websocket/WebSocketConfig.java`
- 前端：`src/utils/partnerSocket.js`

### 5. DeepSeek

情绪建议和周报分析不是写死模板，而是实时请求 DeepSeek 接口。

使用位置：

- `service/impl/DeepSeekServiceImpl.java`
- `service/impl/EmotionServiceImpl.java`

这里有一个明确约束：如果 DeepSeek 调用失败，接口直接报错，不再返回本地兜底文案。这样做是为了让问题能被看见，而不是悄悄吞掉。

### 6. sensitive-word

树洞帖子和评论不是一刀切全量审核，而是先做敏感词检测。命中敏感词时状态记为待审核，普通内容直接公开。

使用位置：

- `service/SensitiveWordFilter.java`
- `service/impl/TreeHoleServiceImpl.java`

### 7. Vue 3 + Vue Router + Pinia

前端的页面、路由和会话状态都在这里完成。

使用位置：

- 路由：`src/router/index.js`
- 会话状态：`src/stores/session.js`
- 页面：`src/views/`

### 8. ECharts

日报、周报、管理后台看板都需要图表。这个项目用 ECharts 统一处理折线图、柱状图、饼图。

使用位置：

- `src/views/report/DailyReportPage.vue`
- `src/views/report/WeeklyReportPage.vue`
- `src/views/admin/AdminDashboard.vue`

## 四、后端关键代码说明

### 1. 用户登录与身份识别

文件：`emolink-backend/src/main/java/com/emolink/service/impl/UserServiceImpl.java`

这部分负责三件事：

- 校验用户名和密码
- 校验用户是否被禁用
- 返回 token、用户基础信息和 `role`

这里的 `role` 是后面管理后台分流的关键。前端正是根据这个字段判断登录后跳去用户端还是管理端。

### 2. 权限拦截

文件：`emolink-backend/src/main/java/com/emolink/interceptor/JwtInterceptor.java`

这个拦截器负责统一处理：

- token 缺失
- token 过期
- 用户不存在
- 用户已禁用
- 非管理员访问 `/api/admin/**`

这样做的好处是权限规则集中，不会散在每个接口里。

### 3. 情绪日记和报告

文件：`emolink-backend/src/main/java/com/emolink/service/impl/EmotionServiceImpl.java`

这个类是情绪模块的主干，负责：

- 新增和更新情绪日记
- 生成 DeepSeek 建议
- 计算日报分布和时间轴
- 生成周报分布、七日平均强度
- 把周报统计结果落到 `emotion_report`

这里的实现思路很明确：用户原始记录存在 `emotion_diary`，周报则是把一周统计结果整理后存入 `emotion_report`，下次再看周报时可以复用已有分析结果。

### 4. 知识库推荐和收藏

文件：`emolink-backend/src/main/java/com/emolink/service/impl/ArticleServiceImpl.java`

文章模块主要做了四件事：

- 文章分页和搜索
- 文章详情阅读量累计
- 收藏和取消收藏
- 根据最近情绪记录推断偏好分类，返回推荐文章

推荐逻辑不是随机返回，而是先看用户最近 20 条情绪日记，再把 dominant emotion 映射成文章分类。

### 5. 树洞审核链路

文件：`emolink-backend/src/main/java/com/emolink/service/impl/TreeHoleServiceImpl.java`

帖子和评论发布时都会先过敏感词检测：

- 命中敏感词：状态置为 `0`，等待管理员审核
- 普通内容：状态置为 `1`，直接公开

评论审核还有一个细节：管理员通过或删除评论时，帖子评论数会同步修正，避免前台数字和实际列表对不上。

### 6. 伙伴匹配和消息发送

文件：`emolink-backend/src/main/java/com/emolink/service/impl/PartnerServiceImpl.java`

这块处理的是“先匹配，再聊天”的流程：

- 用户加入匹配队列
- 系统寻找最早的等待记录
- 只允许和其他账号匹配，不允许自己匹配自己
- 匹配成功后通过 WebSocket 推送事件
- 发消息时校验当前匹配状态是否有效

### 7. 管理后台

文件：

- `emolink-backend/src/main/java/com/emolink/controller/AdminController.java`
- `emolink-backend/src/main/java/com/emolink/service/impl/AdminServiceImpl.java`

这里集中承接管理后台的 14 个接口。实现上没有拆得很花，而是按照后台实际页面的维度组织：

- 数据概览
- 用户管理
- 文章管理
- 帖子审核
- 评论审核

这种做法维护成本低，定位问题也直接。

### 8. 上传和静态资源映射

文件：

- `emolink-backend/src/main/java/com/emolink/config/CorsConfig.java`
- `emolink-backend/src/main/java/com/emolink/controller/FileController.java`

上传目录现在使用相对路径 `uploads/`。服务启动后会把 `/uploads/**` 映射到当前运行目录下的 `uploads/` 文件夹，不依赖任何本机绝对路径。

## 五、前端关键代码说明

### 1. 路由组织

文件：`emolink-frontend/src/router/index.js`

路由分成两组：

- 用户端：挂在 `AppLayout`
- 管理端：挂在 `AdminLayout`

同时在全局前置守卫里判断：

- 是否已登录
- 是否具备管理员角色

### 2. 会话状态

文件：`emolink-frontend/src/stores/session.js`

这个 store 负责保存：

- token
- 当前用户资料
- 角色信息

角色既写入状态，也写入本地缓存，这样页面跳转和刷新都能保持一致。

### 3. 登录页

文件：`emolink-frontend/src/views/auth/LoginPage.vue`

登录成功后，会根据接口返回的 `role` 做跳转：

- `admin` -> `/admin/dashboard`
- `user` -> `/dashboard`

这个地方决定了系统是“单登录入口，双业务端”。

### 4. 日报和周报页面

文件：

- `emolink-frontend/src/views/report/DailyReportPage.vue`
- `emolink-frontend/src/views/report/WeeklyReportPage.vue`

这两个页面都做了同样的处理：先请求数据，等真实 DOM 渲染出来，再初始化 ECharts。这样可以避开骨架屏阶段图表容器还不存在导致的空白问题。

### 5. 伙伴信箱 WebSocket 客户端

文件：`emolink-frontend/src/utils/partnerSocket.js`

前端通过 STOMP 客户端订阅两个通道：

- `/user/queue/partner/message`
- `/user/queue/partner/match`

这样既能收到新消息，也能收到匹配成功、结束聊天之类的事件。

### 6. 管理端布局

文件：`emolink-frontend/src/components/layout/AdminLayout.vue`

后台独立布局和用户端完全分开，侧边栏只保留后台需要的导航项。这样做可以让后台样式、交互节奏和用户端互不干扰。

## 六、数据库结构怎么服务业务

| 表名 | 作用 |
|------|------|
| `user` | 账号、角色、状态、匿名昵称 |
| `emotion_diary` | 原始情绪记录 |
| `emotion_report` | 日报/周报缓存结果 |
| `article` | 心理知识文章 |
| `article_favorite` | 文章收藏 |
| `tree_hole_post` | 树洞帖子 |
| `tree_hole_comment` | 树洞评论 |
| `tree_hole_like` | 树洞点赞 |
| `partner_match` | 匹配关系 |
| `partner_message` | 伙伴消息 |

几个关键字段：

- `user.role`：区分普通用户和管理员
- `user.status`：控制账号是否允许登录
- `tree_hole_post.status`、`tree_hole_comment.status`：控制是否待审核
- `partner_match.status`：控制匹配中的等待、已匹配、已结束

## 七、代码层面的取舍

### 1. 文章封面整体移除

之前文章带封面时，前台展示效果不稳定，而且后台也要承担比例和上传成本。现在文章模块按纯文本处理，数据结构更干净，管理端也更省事。

### 2. 审核逻辑只拦截敏感内容

不是所有树洞内容都先进入人工审核，而是让敏感词检测先做第一道筛选。这样既保留审核能力，也不会让正常用户的发言全部被堵住。

### 3. 上传目录不用绝对路径

这件事对交付特别重要。上传目录改成相对路径后，项目移动到别的电脑仍然能跑，不需要去改某个开发机的本地目录。

1. `UserServiceImpl`
